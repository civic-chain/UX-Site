Workflow capability cards

One component. Same copy. Three honest reads. This page is only here to help us decide what shape these cards should take.

Baseline

Current live component

Open-first reference. The full argument stays visible so we can judge hierarchy, density, and surface quality without reveal motion.

01

Contract record

Use when scope, approvals, and status need to stay in one place.

Keep the contract readable from the first decision onward instead of rebuilding the story across email, PDFs, and follow-up.

02

Controlled spend

Use when vendor spend should stay tied to the approved job.

Set spending boundaries inside the contract instead of relying on reimbursement and after-the-fact cleanup.

03

Bid publishing

Use when the town is opening the work.

Publish the request with budget, timeline, and a visible starting record instead of private handoff and disconnected attachments.

04

Vendor payment card

Use when work needs to start without payment delay.

Fund the winning vendor through a ready-to-use virtual card so the job can begin the same day the contract is awarded.

05

Live spend monitor

Use when field activity needs to stay visible while work is happening.

Watch card activity, merchant context, and approval outcomes in motion instead of waiting for invoices or month-end reconciliation.

06

Burn-rate alerts

Use when the approved pool is being used faster than expected.

Catch contracts that are running hot before field work stalls or finance has to scramble.

07

Completion record

Use when finished work needs a formal checkpoint.

Turn work completion into a visible approval step before the final release moves forward.

08

Fast residual payout

Use when the job is approved and the remainder should move quickly.

Release the remaining contract payment in seconds instead of stretching closeout into another waiting cycle.

09

Public ledger

Use when residents or oversight need the record without a request.

Keep contract activity visible on a public ledger so the audit trail does not depend on FOIA follow-up or manual reconstruction.

10

Export-ready reporting

Use when the contract needs to move into audit, treasury, or council review.

Pull the contract into downstream reporting without rebuilding the packet by hand.

11

Selective public input

Use when a town wants an optional public-input layer.

Document advisory input where it helps without turning every contract into a public vote by default.

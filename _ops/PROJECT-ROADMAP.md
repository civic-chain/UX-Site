# Project Roadmap

## Цель

Внутренняя мастерская дизайнера-CTO для CivicChain landing-страниц. Главная
цель — **отдать клиенту красивые лендинг-страницы** с нашей улучшенной
дизайн-системой, свободной публичной page-итерацией и явными дизайнерскими
сокращениями слабых секций. Вторичная цель — **передать кодовую базу для их
LLM-агента** в красивом виде. Структурная санитария кода — это инструмент для
дизайнера, чтобы было легче доводить визуал до красоты, а не самоцель.

## Стадии

### 1–5. Фундамент, дизайн-система, клиентская синхронизация, чистота, первая красота ✓

Закрыты. Рабочий контракт, доменные rule-файлы, единая дизайн-система,
синхронизация публичных страниц с клиентским export'ом, структурная чистота
кода и первая визуальная полировка публичных страниц на утверждённом направлении.
Границы owner/scope и детали — в `AGENTS.md`, скилле `2civic-design`,
`_ops/rules/`; история — в `git log`.

### 6. Конкурс смелых креативных кандидатов на главную ✓ (закрыт)

`/landing-v3`..`/landing-v6` были смелыми расходящимися креативными гипотезами
главной (процесс, records / открытость, люди, кинетическая типографика).
Показаны основателю. Решение владельца: ни один не уходит в продакшн как есть —
дальнейшая работа сходится на одну поверхность (Стадия 7), а не плодит
варианты. Runtime-маршруты Stage 6 удалены по решению владельца вместе с
неиспользованным `/landing-v7`; историю смотреть через git и исторические
маркетинговые спеки, не как live surfaces.

### 7. Главный лендинг promoted to `/` ✓

`/landing-v2` был рабочей копией продакшн-`/` для следующего главного
лендинга. Решение владельца от 2026-06-19: эта версия стала главной на `/`.
Предыдущая первая главная сохранена как noindex-архив `/landing-v1`, а старый
preview URL `/landing-v2` редиректит на `/`.

Несущий ход стадии — **анимированная hero-история справа сверху**: одна живая
публичная запись, которая своим появлением рождает сразу скорость, прозрачность
и экономию (один механизм — три выгоды, сворачивающиеся в выгоду города).
Анимация заменяет чтение, а не украшает; остаётся in-brand; claim-дисциплина
(Modeled / Target / Actual) — закон. Остальные секции поднимаются от
продакшн-базы поверх этого hero. Правила движения и бренда — в
`_ops/rules/landing-design-and-brand.md` и `components/motion/`.

К концу стадии: `/` — утверждённый главный лендинг, готовый к показу клиенту по
Vercel preview-ссылке. Дальнейшие правки главной живут в `app/(site)/_sections`.

### 8. Передача кодовой базы для LLM-агента

Финальная стадия (приоритет №2). Код переходит к клиенту в виде, годном для их
LLM-агента (если будут использовать). Формат сдачи (push в их репо / архив /
другое) уточняется ближе к стадии. Acceptance: `AGENTS.md` / `_ops/rules/` /
`README.md` / скилл `2civic-design` синхронизированы с реальным кодом;
cold-LLM walkthrough пройден на свежей сессии.

К концу стадии: кодовая база в руках клиента; полный on-ramp холодному агенту.

### 9. Дизайн-система как внутренняя документация ✓

`/brand` — техническая документация дизайн-системы для команды и handoff-LLM.
Она показывает, что существует, как это применять и какие ограничения держать.
Тон короткий, инструктивный и полезный; это не public sales copy и не вторая
база знаний. Дубль-витрина `/dev/components`, старые landing-варианты и
демо-интерфейсы сняты с runtime.

### 10. Консолидация дизайн-системы и уборка документации ✓

Закрыта. Дизайн-система сведена к одной рабочей модели, runtime и policy-слой
стерегут её в коде, а Markdown больше не хранит подробные token inventories,
migration closeout и validator history. Единственный авторитет дизайна —
скилл `2civic-design`; подробности текущей реализации читаются из
кода и проверок. Закрытый phase-10 planning слой удалён из active `_ops/plans`;
история остаётся в `git log`.

# Instruction Hygiene

## Цели

- `AGENTS.md`, `CLAUDE.md`, README и `_ops/rules/` маршрутизируют к живым owners, а не копируют тела skills.
- Claude Code / Codex / Cursor получают общий контракт без дублей; runtime-специфика остаётся в своём файле.
- Инструменты и hooks описаны как routing и checks, не как второй каталог документации.

## Перед Правкой Инфраструктуры

- Перед правкой Claude-Code-инфры — сверить актуальную документацию; встроенная память модели может быть устаревшей.
- Перед правкой Codex hooks/config/runtime — читать живые локальные config/scripts и текущий `SKILL.md`, не писать ключи из памяти.
- Перед правкой skill-routing — проверить текущие handles в среде; старые имена из task-файлов или памяти не переносить.

## Структура Файлов

- `AGENTS.md` = общий контракт всех агентов. НЕ загружается Claude Code автоматически — нужен `@AGENTS.md` импорт в `CLAUDE.md`.
- `CLAUDE.md` = однострочный shim `@AGENTS.md`. Не несёт отдельной памяти, команд или правил.
- README = человеческий on-ramp и команды; не rulebook.
- `_ops/rules/*.md` = правила по доменам. Источник правды для проектных правил.
- `_ops/PROJECT-ROADMAP.md` = цель + стадии.
- `scripts/checks/instruction-drift.mjs` = mechanical guard против устаревших routes/handles.
- Дизайн-скилл `2civic-design` зеркалится в `.claude/skills/` и `.codex/skills/`.
  Любая правка — новый компонент, уточнённое правило, новый reference-файл — идёт
  в ОБЕ копии синхронно. `reference/`-файлы между ними байт-идентичны (стережёт
  `instruction-drift.mjs`); тела `SKILL.md` могут расходиться только в
  runtime-специфике (напр. граница `2civic-img-gen` в Codex).
- Один файл — одна роль. Дубли вычищать.

## Папочные Инструкции и Скилл-Хранитель (Гарантия Качества)

Папочные `AGENTS.md` грузятся автоматически в каждой сессии, работающей в их
папке (через `@AGENTS.md`-шим в `CLAUDE.md`) — это единственная поверхность,
которую агент гарантированно прочитает до того, как напишет код.

Знание дизайна (бренд-закон, компоненты, контракт цвета поверхности, токены,
структура) держит **один хранитель — скилл `2civic-design`**; всё на него
ссылается, никто не дублирует его тело. Папочный `AGENTS.md` несёт не копию
контента, а **guaranteed-read императив**: «перед визуальным/дизайн-системным
кодом вызови `2civic-design`» плюс одно кардинальное правило (бери компонент, не
лепи руками; цвет едет от поверхности) — safety-net на случай, если агент не
вызовет скилл. Глубина — в скилле, не в папке.

Прочие folder-specific actionable правила (не про дизайн) живут в папочном
`AGENTS.md` полностью — он автозагружается, это и есть гарантия их чтения.
`_docs/**` и неподтянутые `_ops/rules/*` грузятся по запросу — ссылка на них
дополняет правило, не заменяет триггер.

Тела skills не копируются — skills вызываются, не читаются inline; в инструкции
остаётся «когда вызвать». CLI-инструменты — лестница выбора, не полный список
бинарей.

## Hooks

- Codex hooks для этого проекта выключены в локальном `.codex/config.toml`.
  Не добавлять Markdown hooks и не строить workflow на `1md-*` skills / `md`
  CLI без явной просьбы пользователя.
- Минимум хуков на уровне проекта. Дисциплина rule-anchor приходит из глобального Claude-конфига пользователя — не дублировать здесь.
- Новые project-level хуки — только по явному запросу пользователя.

## Кастомные Команды И Subagent'ы

`.claude/commands/`, `.claude/agents/` — создавать после **3+ ручных повторений** одного паттерна. Сейчас 0 — не создавать.

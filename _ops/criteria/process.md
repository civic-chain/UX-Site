# Process

Дисциплина управления файлами и текстами в проекте.

## Цели

- Минимум файлов в проекте, максимально сжатый текст.
- Criteria смотрят вперёд: правила и цели вместо архивов решений и ошибок.
- При сдвиге приоритетов или конфликте — переписать существующее, не накапливать.
- На сессии агент читает только релевантное под текущую задачу.

## Стиль Письма (Краткость)

- Ни одного лишнего слова. Самая короткая формулировка, которая сохраняет смысл.
- Документы и тексты держим максимально сжатыми.
- При конфликте старого и нового — переписываем, а не накапливаем.
- Без необходимости новые файлы не создаём.

Причины: меньше сигналов = LLM легче читать; чище для передачи другому человеку; комфортнее жить.

## Языковая Граница

Rule: Handoff-facing docs and agent instructions outside `_ops/` should be English; `_ops/**` may remain Russian as the owner's working layer.
Why: The codebase may be handed to an American developer, while `_ops` stays useful as the user's live operating memory.

## Архивы Запрещены

- Не вести хронологические журналы решений или ошибок.
- Урок, который заслуживает запоминания, кристаллизуется в критерий в `_ops/criteria/`.
- Урок, который не заслуживает — не нужен. Не каждый эпизод требует правила.

## Локальные Артефакты

Rule: Scratch, логи, отчёты и временные выходы инструментов держать в `.ignore/`, а не в корне.
Why: Чистый корень легче читать пользователю и внешнему программисту.

Rule: Не прятать рабочие папки быстрого запуска (`node_modules`, `.next`, `.vercel`) без отдельного решения.
Why: Они некрасивые, но их перенос может замедлить или сломать локальную работу.

## GitHub Как Бэкап

- Проект сейчас личный: один владелец, без командной веточной дисциплины.
- GitHub для пользователя — облачный бэкап локального `main`, не рабочая веточная модель.
- По прямой команде «пушим всё» публиковать весь неигнорируемый `main`, без PR и без веток, если пользователь отдельно не попросил другое.
- Перед push показать/проверить только реальный риск: проверки, мусор, запрещённые текущими criteria файлы.
- В `civicchain-v2` грязное локальное дерево не считается чужим риском само по себе; не тормозить работу только из-за `git status`, но не откатывать и не удалять незнакомые правки без явной просьбы.

## Дисциплина Кода

Общая инженерная философия проекта. Применяется ко всему коду — landing-секциям, demo-интерфейсам, токенам, инструкциям. Закреплена в корневых AGENTS.md и README.md как «предпочтение разработчику» — каждый новый человек или LLM-агент должен сразу понимать, по каким правилам мы работаем.

- **Простота важнее абстракции.** Меньше слоёв = легче войти cold-reader'у за 30 минут. Не плодить React variant API, scope mechanisms, parallel namespaces «на будущее». Use case должен быть реальным, не гипотетическим.
- **Named tokens, не scope mechanisms.** Цвета, формулы, повторяющиеся значения живут под именами в `tokens.css`. JSX/CSS читает `var()` напрямую. Scope-классы (`.card-tone-*`, `.X-tone-Y`) скрывают логику и требуют двойной навигации, чтобы понять одно правило.
- **Inline в месте использования для one-off, named token при повторе.** Если формула в одном месте — пиши прямо в JSX. Если повторяется ≥2 раза — поднимай в палитру / namespace. Single-use tokens создают шум для cold-reader'а.
- **Reuse + extension прежде нового компонента/файла.** Новый primitive — только при доказанном повторе ≥3 раза. Сначала добавить tone-variant к существующему компоненту, потом думать о новом.
- **Explicit над magic.** Имя описывает контекст использования или конечный цвет, не реализацию. `--paper-cream` (lifted bright cream surface) вместо `--card-cream-bg` (зависит от scope). Cold-reader читает значение, не угадывает где scope установлен.
- **Никаких структурных правил «как должны выглядеть карточки».** Дизайнер свободен делать карточки разными. Чем меньше навязанных шаблонов — тем меньше препятствий для итерации визуала.
- **Cold-reader Stage 7 как лензa.** Codebase уйдёт внешнему программисту или LLM-агенту клиента. Каждое архитектурное решение проходит проверку: «понял ли бы это за 30 минут новый человек, который не видел проект?». Если нет — упростить.
- **Минимум вложенности.** Route group существует только если у него отдельный `layout.tsx`, отличный от соседей. Подпапка существует только если отвечает на один очевидный вопрос за 4 слова. Закрытые phase-планы живут в `git log`, не на диске. Применяется к `app/`, `components/`, `lib/`, `_ops/plans/`.

Why: проект небольшой (одна landing-страница + несколько marketing-маршрутов + decorative demo-интерфейсы). Архитектура enterprise-масштаба здесь — overhead. Простота снижает стоимость каждой итерации, ускоряет передачу клиенту, освобождает дизайнера от структурных шаблонов.

## Дисциплина Criteria

- Criteria — правила, красные линии, факты пользователя/проекта. Не проза, не нарратив, не описания процессов, не чеклист тестировщика.
- Один пункт = одно правило в самой короткой формулировке. Объяснение «почему» — только если правило без него хрупкое.
- Примеры — только если они нужны для распознавания правила (markers off-brand). Иначе — в код или `_docs/`.
- Формат: цель наверху, затем критерии по домену.
- Каждый файл — один домен. Файл вырастает — пересмотреть: объединить, сжать или разделить.
- Устойчивое правило всплыло в разговоре — агент обновляет релевантный criteria-файл в той же сессии, не откладывает.
